## Fix: thesis search dead on trade pages (RCS app)

**Repo:** `/Users/jun/Nextcloud/Trading/research-capture-system` (sibling of the trading-infrastructure repo this session opened in). No backend change; no changes to trading-infrastructure.

**Root cause:** The thesis-search `<input>` is wrapped in Alpine `<template x-if="canvasId">`. HTMX only wires `hx-*` attributes at load and on HTMX swaps — not on Alpine `x-if` insertions. So after picking a canvas, the thesis input gets injected into the DOM but never wired, no `/thesis/search` request is sent, no thesis can be selected, and the Activate button stays disabled. The backend is correct and needs no change.

### Changes

**1. `research/frontend/templates/trade/detail.html`** (activate form, lines 124-143)
- Remove the `<template x-if="canvasId">` wrapper around the thesis input + results div.
- Always render the thesis input/results in the initial DOM, and toggle *visibility* with `x-show="canvasId"`.
- Keep the existing `<template x-if="!canvasId">` "Select a canvas first." hint and the `thesisId` selected hint unchanged.
- Result: HTMX wires the input once at page load; `/thesis/search` fires on typing exactly like the working typeaheads (`setup/detail.html`, `observation/detail.html`, `canvas/panel.html`).

**2. `research/frontend/templates/trade/new.html`** (fast-path, lines 131-152) — identical `x-if` → `x-show` fix.

Both pages already gate the input's *purpose* behind canvas selection via the `data-typeahead-canvas-scoped` attribute read in `base.html:247-250` (which sends `canvas_id` only when the Alpine component has `canvasId`), so removing the DOM gate does not change search semantics — it just makes the input reachable by HTMX.

- Quick confirmation that no other `trade/*` page uses the gated pattern (only these two do; every other thesis typeahead already renders in initial DOM).
