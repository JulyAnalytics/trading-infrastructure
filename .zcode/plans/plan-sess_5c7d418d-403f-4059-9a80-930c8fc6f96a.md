### Part 2 — The proposed §7 section (to be appended to creating-a-theme.md)

> ## 7. Font packs — swapping typefaces without breaking the UI
> A **font pack** is a named set of values for the three stack tokens (`--font-sans`, `--font-body`, `--font-mono`), optionally plus a proportional scale adjustment. A pack is not a new theme — it layers onto any theme block. Guarantee: any pack that follows the contract below changes *look*, not *function*.
>
> **7.1 The three font roles**
> | Role | Token | Consumers | Utility it protects |
> |---|---|---|---|
> | Chrome | `--font-sans` | body default; sidenav, nav links, h1–h3, chips, tabs, buttons, table headers | density, scanability, uppercase+letter-spacing micro-labels (0.4–1px tracking) |
> | Reading + forms | `--font-body` | `input/textarea/select`, `p`, `.field .label/.help`, `.notice/.error/.ok-box`, `.loading` | prose legibility, form consistency; **the serif/sans play area** |
> | Data | `--font-mono` | `.mono`, `textarea.json` — IDs, hashes, ULIDs, timestamps, dates, JSON/YAML, log tails, param hashes | char-count truncations (`slice(0, 34)`), copy/paste integrity, 0/O/1/l distinction |
>
> **7.2 The utility contract** (numbered rules):
> 1. **Data stays mono** — never give data-shaped text a proportional face; truncation and alignment assume mono advance widths.
> 2. **Numbers stay tabular** — `table.data` and `.scorebar .val` (fixed 48px, right-aligned) rely on `font-variant-numeric: tabular-nums`. A different family for numbers is allowed only if the face ships tabular figures.
> 3. **Chrome stays sans by default** — serif on chrome is allowed only with letter-spacing tokens reduced and the 208px sidenav / chip / tab padding re-verified for wraps.
> 4. **Forms + prose are the play area** — serif goes in `--font-body`; sizes stay on the `--fs-*` ramp (scale the whole ramp proportionally if the face runs small — serif x-heights read ~5–10% smaller — never one token); `textarea.json` stays mono.
> 5. **Charts follow the pack** — `usePlotTheme()` sets `font.family` from `--font-sans`; chart text is label-like, so it follows chrome, not body.
> 6. **Every stack ends in a system fallback** (`serif`/`sans-serif`/`monospace`) so packs degrade gracefully offline.
>
> **7.3 Swapping in a pack** — 4 steps: self-host `@font-face` once above the theme blocks (system faces need none); change up to 3 tokens in the target theme block; optionally scale the `--fs-*` ramp proportionally; run the §7.5 checklist.
>
> **7.4 Serif playbook** — works: prose, notes/boxes, form fields, long-form outputs (weekly review, interpretation cards). Avoids: micro-labels (chips/table headers at 11.5px), dense tables, mono data. Uppercase+tracking+serif = clutter; humanist sans (serif prose, sans UI) is a valid middle pack.
>
> **7.5 Font-pack verification checklist** — build clean; data audit (`.mono` sites still data-shaped); numeric audit (Marcus scorebars/returns table aligned, 48px column unclipped); no sidenav/chip/tab wraps; chart `_fullLayout.font.family` = chrome stack (Playwright); `textarea.json` still mono; screenshot Command Deck + Params.
>
> **7.6 Worked example — "serif reading" pack** (shown as a 3-line token diff against any theme, not a new theme):
> ```css
> --font-sans: -apple-system, "Segoe UI", Roboto, "Helvetica Neue", sans-serif;
> --font-body: Georgia, "Times New Roman", serif;   /* the pack swap */
> --font-mono: ui-monospace, SFMono-Regular, Menlo, monospace;
> ```
> plus a note: self-host Charter/Bookerly via `@font-face` for a less-default look.
