**2. `docs/wiki/06-knowledge/rcs-trading-contracts.md`** (the contract spec — the reference doc)

The deterministic substrate. Structured so each section can later become code, but stands alone as a spec today. Sections:

- **§1 The capability map.** For each of the 8 RCS entities: its semantic role, its trading counterpart, the integration *type* (validation / analysis / evidence / triage / risk / feedback / scheduling / memory), what it needs from trading, what it offers trading. Pulls the entity fields from the RCS schema (instrument, narrative, win_condition, kill_conditions, decision_points for thesis; invalidation_conditions with probability/lead_time for canvas; etc.) so each contract names real fields.

Includes the authority hierarchy (Jordan hard-override > Priya research gate > Sam operational gate > Kai soft-veto > Marcus indirect > Alex prioritization > Elena advisory) because that determines which checks can be skipped and which cannot.

- **§4 The seven Priya↔Jordan handoff contracts** (the load-bearing ones the distillations justify): edge-haircut (Thorp §7.3 — the single most important bridge), covariance-matrix handoff (normal→stress), CPCV-paths→scenario-library, triple-barrier→Greeks-monitoring-triggers, transaction-cost→stress-bid/ask, strategy-risk vs portfolio-risk separation, trial-count propagation.
