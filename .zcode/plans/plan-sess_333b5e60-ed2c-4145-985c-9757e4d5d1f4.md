## Fix: scale `hy_spread` / `yield_curve_10_2` chart data to bps

### Root cause (already diagnosed)
`systems/api/routes/marcus.py:251-279` `chart_series()` plots the raw `macro_series.value` (FRED percent: HY ~2.7, curve ~0.4) on the same Y axis as the threshold overlays (`regime_thresholds`, in bps: 300/450/600/900 and -10/50/100/200). Plotly autoranges to fit the bps thresholds and squashes the percent-scale data line into an apparently flat hairline. VIX and breakeven are unaffected because their thresholds share the data's units.

### Change — one file, one function
**`systems/api/routes/marcus.py`** — in `chart_series()`:

1. Add a module-level `_BPS_CONVERSION` map (placed right after `_SERIES_CHARTS`):
   ```python
   _BPS_CONVERSION = {
       "hy_spread":        20.0,  # mean |value| < 20 → stored in percent, scale ×100
       "yield_curve_10_2": 5.0,   # mean |value| < 5  → stored in percent, scale ×100
   }
   ```
2. Between fetching `data` and building `fig`, compute the scaled Y values:
   ```python
   values = [r["value"] for r in data]
   scale = _BPS_CONVERSION.get(series_id)
   if scale is not None and values:
       mean_abs = sum(abs(v) for v in values if v is not None) / len(values)
       if mean_abs < scale:
           values = [v * 100 if v is not None else v for v in values]
   ```
3. Use `values` instead of `[r["value"] for r in data]` in the scatter `y`.

This mirrors the proven heuristic in the retired Dash builders (`systems/dashboard/macro_dashboard.py:232-233, 274-275`) — same `abs().mean() < threshold` guard, same `×100`. The guard self-disables if the data is ever persisted in bps upstream, so it won't double-scale.

Why scale the data rather than the thresholds:
- The chart titles already say `(bps)` (`marcus.py:245-246`), so bps is the intended display unit — scaling the data makes the titles truthful.
- The params `regime_thresholds` are also consumed by the component scorers in bps; leaving them untouched keeps that contract intact.
- VIX and breakeven are not in the map, so their behavior is unchanged.

### Out of scope
- No DB migration, no change to stored values, no change to the regime classifier (which has its own unit handling and is unaffected).
- No frontend change — the figure JSON is rendered as-is by `PlotlyFig`.
